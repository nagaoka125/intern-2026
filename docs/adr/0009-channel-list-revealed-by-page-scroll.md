# チャンネル一覧はページスクロールで表示し、視聴画面本体の高さは固定する

ADR 0001・0002は、動画・コメント欄・送信欄が常に1画面に収まるよう縮小するレイアウトを前提にしていた。チャンネル一覧セクションを追加した際、この前提のままだと新しいセクションが増えるたびに視聴画面本体（動画・コメント欄・送信欄）が圧迫されて縮んでしまう問題が生じた。そこで、`header`と`.app-container`を`.viewer-frame`という新しいラッパーでまとめ`height: 100vh`を指定し、視聴画面本体は常にちょうど1画面分の高さに固定するように変更した。チャンネル一覧はこのラッパーの外側に置かれ、画面に収まりきらない分はページ全体をスクロールしないと見えないようにする。

`height`ではなく`min-height: 100vh`で最初に実装したところ、それは「最低でもこの高さ」という伸縮可能な下限にすぎず、コメントが増えると`.viewer-frame`自体が中身に押し出されて伸びてしまい、ADR 0001・0002が前提とする「あふれた分はコメント欄の内部スクロールに任せる」という挙動が壊れる不具合を引き起こした。視聴画面本体を伸びない箱として固定するには`height`が必要で、`min-height`では代用できない。

## Consequences

視聴画面本体は今後どんなセクションが下に追加されても縮まなくなる一方、チャンネル一覧のような補助的なセクションは初期表示では見えず、視聴者が明示的にスクロールしないと気づけない。今後、視聴画面本体の外側（`.viewer-frame`の外）に新しいセクションを追加する場合はこのスクロール表示の方針を踏襲し、視聴画面本体そのものを拡張する場合はADR 0001・0002の「1画面に収める」制約を引き続き意識する必要がある。`.viewer-frame`の高さ指定を`min-height`に変更したくなった場合は、この不具合が再発することを思い出すこと。
